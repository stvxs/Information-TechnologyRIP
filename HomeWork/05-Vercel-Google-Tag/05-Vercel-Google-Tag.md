## 2. Теоретическая часть

### 2.1. Google Analytics 4

Google Analytics 4 (GA4) - инструмент веб-аналитики, предназначенный для сбора, обработки и анализа информации о взаимодействии пользователей с сайтом.

С помощью GA4 можно:
- Отслеживать просмотры страниц.
- Анализировать действия пользователей.
- Определять источники переходов на сайт.
- Изучать эффективность рекламных кампаний.
- Анализировать поведение посетителей.
- Просматривать поступающие события в режиме реального времени.

Для сбора данных используются ресурс GA4, поток веб-данных и идентификатор измерения Measurement ID.

### 2.2. Web Data Stream и Measurement ID

Web Data Stream - поток веб-данных, через который информация с сайта поступает в Google Analytics 4.

Measurement ID - уникальный идентификатор потока, обычно имеющий формат `G-XXXXXXXXXX`.

Он используется в коде Google Tag для указания ресурса, в который необходимо отправлять аналитические события.

В рамках занятия рассматривалась настройка существующего учебного потока: изменение адреса сайта и названия потока без обязательного создания нового потока данных.

**Общий пример Measurement ID:**

```text
G-XXXXXXXXXX
```

**Мой вариант:** используется фактический Measurement ID потока GA4, подключённого к сайту `ga4-analytics-lab-stvxs.vercel.app`.

### 2.3. Google Tag

Google Tag - код, устанавливаемый на сайт для передачи информации в Google Analytics 4.

После подключения тега браузер может отправлять события, например `page_view`, фиксирующее просмотр страницы.

Основные элементы Google Tag:

- `gtag.js` - библиотека Google для работы с тегом.
- `dataLayer` - очередь данных и команд, используемая тегом.
- `gtag()` - функция для передачи команд.
- `gtag('js', new Date())` - инициализация тега.
- `gtag('config', 'G-XXXXXXXXXX')` - настройка тега для соответствующего потока GA4.

Код Google Tag размещается в секции `<head>` HTML-документа в соответствии с инструкциями Google. Для загрузки библиотеки используется атрибут `async`, позволяющий не блокировать загрузку страницы ожиданием скрипта.

Для корректной работы необходимо использовать собственный Measurement ID.

### 2.4. GitHub

GitHub - платформа для хранения исходного кода и управления версиями проектов.

GitHub позволяет:
- Хранить файлы сайта.
- Создавать собственные копии учебных проектов.
- Сохранять историю изменений.
- Передавать обновлённый код в удалённый репозиторий.
- Интегрировать проект с Vercel для автоматической публикации.

Основные понятия:

- **Repository** - репозиторий с файлами проекта.
- **Commit** - фиксация изменений в истории репозитория.
- **Push** - отправка локальных изменений в удалённый репозиторий.
- **Clone** - копирование репозитория на компьютер.

### 2.5. Visual Studio Code

Visual Studio Code (VS Code) - редактор кода, предназначенный для разработки, редактирования и проверки файлов сайта.

С его помощью можно:
- Открывать и редактировать HTML-файлы.
- Работать с CSS и JavaScript.
- Запускать локальную версию сайта.
- Проверять изменения.
- Выполнять Commit и Push.
- Синхронизировать локальный проект с GitHub.

VS Code позволяет выполнять основные действия с кодом и репозиторием в одном рабочем пространстве.

### 2.6. Vercel

Vercel - платформа для публикации сайтов в интернете.

Она поддерживает автоматическое развёртывание проекта при обновлении подключённого GitHub-репозитория.

Основные понятия:

- **Deployment** - процесс публикации определённой версии проекта.
- **Production** - рабочая опубликованная версия сайта.
- **Production URL** - постоянный публичный адрес сайта.
- **Root Directory** - корневая папка проекта.
- **Build Command** - команда сборки проекта.

Для статического сайта на HTML, CSS и JavaScript отдельная команда сборки обычно не требуется.

**Общий пример адреса сайта:**

```text
https://ваш-проект.vercel.app/
```

**Мой опубликованный сайт:**

https://ga4-analytics-lab-stvxs.vercel.app/

### 2.7. Связь GitHub, VS Code и Vercel

Процесс обновления сайта состоит из нескольких этапов:

1. Код редактируется в VS Code.
2. Изменения фиксируются с помощью Commit.
3. Изменения отправляются в GitHub с помощью Push.
4. Vercel обнаруживает новый Commit.
5. Запускается Deployment.
6. После успешного развёртывания обновлённая версия становится доступна по Production URL.

Commit и Push выполняют разные функции: первый сохраняет изменения в истории, второй отправляет их в удалённый репозиторий.

После Push необходимо проверить статус Deployment в Vercel, поскольку отправка кода не означает, что публикация уже завершена.

В учебном проекте используется структура статического сайта, состоящего из HTML-страниц, таблицы стилей и JavaScript-файла.

Пример структуры:

├── about.html
├── contacts.html

│   └── style.css

Назначение файлов:

Чтобы отслеживать просмотры всех страниц, Google Tag необходимо устанавливать на каждую HTML-страницу, которая должна передавать данные в GA4.

Локальная версия сайта запускается на компьютере разработчика, например по адресу `http://localhost:5500/`.

Она предназначена для разработки и предварительной проверки.

Опубликованная версия доступна в интернете по постоянному HTTPS-адресу.

**Общий пример:**

```text

```

**Мой вариант:**

Публичный адрес используется для проверки доступности сайта, установки Google Tag, анализа просмотров и тестирования UTM-ссылок.

### 2.10. Событие page_view

`page_view` - событие Google Analytics 4, фиксирующее просмотр страницы.

При загрузке страницы Google Tag может отправить соответствующее событие в GA4.

Для проверки необходимо открыть сайт, перейти между страницами и посмотреть поступающие события в отчёте Realtime.

Наличие события `page_view` является признаком того, что аналитика получает данные о просмотрах. Однако сам факт наличия кода на сайте ещё не гарантирует успешную передачу данных.

### 2.11. UTM-метки

UTM-метки - параметры URL, предназначенные для определения источников переходов и анализа эффективности маркетинговых кампаний.

Основные параметры:

- `utm_source` - источник перехода.
- `utm_medium` - тип канала.
- `utm_campaign` - название кампании.

**Общий пример UTM-ссылки:**

```text
https://ваш-проект.vercel.app/?utm_source=telegram&utm_medium=social&utm_campaign=ga4_lab
```

**Мой вариант UTM-ссылки:**

```text
https://ga4-analytics-lab-stvxs.vercel.app/?utm_source=telegram&utm_medium=social&utm_campaign=ga4_lab
```

В данном примере:

- `utm_source=telegram` - источник перехода Telegram.
- `utm_medium=social` - тип канала Social.
- `utm_campaign=ga4_lab` - название учебной кампании.

UTM-метки позволяют сравнивать переходы из разных источников, например Telegram, VK, YouTube, электронной почты и QR-кода.

Для корректного сравнения необходимо придерживаться единого формата названий и использовать одинаковое название кампании для ссылок, относящихся к одной кампании.

### 2.12. Realtime и обработка аналитических данных

Realtime - отчёт GA4, показывающий поступающие события практически в режиме реального времени.

С его помощью можно проверять:
- Активность пользователей.
- Просмотренные страницы.
- События `page_view`.
- Поступление данных после перехода по UTM-ссылке.

Realtime предназначен прежде всего для оперативной проверки событий. Информация об источниках, каналах и кампаниях может обрабатываться дольше.

Для полноценного анализа привлечения трафика используется стандартный отчёт GA4 «Привлечение трафика».

## 3. Практическая работа

### 3.1. Создание собственного репозитория

Для выполнения задания использовался учебный шаблон сайта `ga4-analytics-lab`.

Последовательность действий:

1. Открыть репозиторий учебного шаблона на GitHub.
2. Выполнить вход в учётную запись.
3. Выбрать `Use this template`.
4. Нажать `Create a new repository`.
5. Указать владельца и название репозитория.
6. Создать собственный репозиторий.

В результате создаётся отдельная копия проекта, которую можно редактировать, обновлять и публиковать независимо от исходного шаблона.

### 3.2. Клонирование проекта в VS Code

После создания репозитория проект необходимо загрузить на компьютер.

Выполненные действия:

1. Открыть Visual Studio Code.
2. Перейти в раздел Source Control.
3. Выбрать `Clone Repository`.
4. Указать адрес собственного репозитория GitHub.
5. Выбрать папку для сохранения проекта.
6. Дождаться окончания клонирования.
7. Открыть проект в редакторе.

После загрузки проверяется структура проекта и наличие основных файлов сайта.

### 3.3. Локальная проверка сайта

До публикации сайта необходимо проверить его работоспособность.

Для этого можно использовать расширение Live Server в VS Code.

Последовательность действий:

1. Открыть файл `index.html`.
2. Запустить локальный сервер.
3. Открыть сайт в браузере.
4. Проверить отображение главной страницы.
5. Проверить оформление и переходы между страницами.
6. Убедиться, что страницы About и Contacts доступны.

Локальная проверка позволяет обнаружить ошибки до размещения проекта в интернете.

### 3.4. Публикация сайта на Vercel

Для размещения сайта в интернете используется Vercel.

Последовательность действий:

1. Открыть Vercel.
2. Авторизоваться через GitHub.
3. Перейти в Dashboard.
4. Выбрать `Add New → Project`.
5. Найти собственный репозиторий.
6. Нажать `Import`.
7. Проверить настройки проекта.
8. Выбрать подходящий вариант Framework Preset для статического сайта.
9. Оставить корневую директорию проекта.
10. Не указывать команду сборки, если она не требуется проекту.
11. Нажать `Deploy`.
12. Дождаться завершения Deployment.

**Общий пример адреса после публикации:**

```text
https://ваш-проект.vercel.app/
```

**Мой опубликованный сайт:**

https://ga4-analytics-lab-stvxs.vercel.app/

После публикации необходимо проверить открытие сайта в браузере и доступность основных страниц.

### 3.5. Настройка Web Data Stream в GA4

Для связи сайта с аналитикой используется Web Data Stream в Google Analytics 4.

Последовательность действий:

1. Открыть Google Analytics 4.
2. Перейти в `Admin`.
3. Открыть `Data streams`.
4. Найти существующий учебный Web Data Stream.
5. Открыть настройки потока.
6. Изменить адрес сайта на адрес опубликованного проекта.
7. При необходимости изменить название потока.
8. Сохранить изменения.

**Общий пример домена для настройки:**

```text
ваш-проект.vercel.app
```

**Мой домен:**

```text
ga4-analytics-lab-stvxs.vercel.app
```

В поле Website URL указывается домен без повторения протокола, UTM-параметров и путей отдельных страниц.

Для работы с существующим потоком используется его текущий Measurement ID. Создание нового потока не является обязательным, если действующий поток предназначен для этого проекта.

### 3.6. Получение кода Google Tag

После настройки потока необходимо получить код Google Tag.

Последовательность действий:

1. Открыть настройки Web Data Stream.
2. Перейти к сведениям о Google Tag.
3. Выбрать `View tag instructions`.
4. Открыть вариант `Install manually`.
5. Скопировать предоставленный код.

Код содержит идентификатор потока и инструкции для подключения аналитики к сайту.

**Общий пример Measurement ID:**

```text
G-XXXXXXXXXX
```

**Мой вариант:** в коде используется фактический Measurement ID собственного потока GA4.

При установке необходимо использовать реальный идентификатор, а не условное значение из примера.

### 3.7. Установка Google Tag на сайт

Для подключения аналитики полученный код необходимо разместить в HTML-документах сайта.

Последовательность действий:

1. Открыть `index.html` в VS Code.
2. Найти секцию `<head>`.
3. Вставить код Google Tag в указанное инструкциями место внутри секции.
4. Повторить установку в `about.html`.
5. Повторить установку в `contacts.html`.
6. Сохранить изменённые файлы.

**Общий пример страницы для установки тега:**

```text
index.html

contacts.html
```

**Мой вариант:** тег устанавливается в HTML-файлы собственного проекта `ga4-analytics-lab-stvxs`.

Установка тега на все необходимые страницы позволяет передавать информацию о просмотрах независимо от того, с какой страницы начинается посещение сайта.

### 3.8. Сохранение изменений в GitHub

После установки Google Tag необходимо сохранить изменения в репозитории.

Последовательность действий:

1. Сохранить изменённые HTML-файлы.
2. Открыть Source Control в VS Code.

4. Добавить необходимые файлы в Staged Changes.

**Общий пример сайта для проверки:**

```text
https://ваш-проект.vercel.app/

**Мой вариант:**

**Мой вариант UTM-ссылки:**

```

В ссылке используются три основных параметра:

## 5. Контрольные вопросы

**1. Что такое Google Analytics 4?**

Это инструмент веб-аналитики, который позволяет собирать и анализировать данные о взаимодействии пользователей с сайтом.

**2. Что такое Google Tag?**

Это код, который устанавливается на сайт для передачи данных в Google Analytics 4.

**3. Для чего нужен Measurement ID?**

Он идентифицирует поток веб-данных GA4, в который отправляются аналитические события.

**4. Для чего используется GitHub?**

Для хранения исходного кода, управления версиями проекта и передачи изменений между разработчиком и удалённым репозиторием.

**5. Чем отличаются Commit и Push?**

Commit фиксирует изменения в истории репозитория, а Push отправляет изменения в удалённый GitHub.

**6. Для чего используется Vercel?**

Для публикации сайта в интернете и автоматического развёртывания новых версий проекта.

**7. Что означает событие `page_view`?**

Это событие, фиксирующее просмотр страницы сайта.

**8. Что позволяет проверить Realtime?**

Поступление событий, активность пользователей и просмотренные страницы практически в реальном времени.

**9. Для чего нужны UTM-метки?**

Для определения источника, типа канала и кампании, с которыми связан переход на сайт.

**10. Почему Google Tag устанавливается на несколько HTML-страниц?**

Чтобы аналитика могла регистрировать просмотры всех необходимых страниц сайта.

**11. Почему данные о кампании могут появляться не сразу?**

GA4 обрабатывает данные о привлечении отдельно от оперативного отображения событий.

**12. Что необходимо проверить, если события не поступают?**

Наличие Google Tag, правильность Measurement ID, актуальность опубликованной версии, настройки согласия и возможную блокировку запросов браузером.
