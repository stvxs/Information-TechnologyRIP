## 3. Теоретическая часть

### 3.1. Что такое Google Analytics 4

Google Analytics 4 (GA4) - это система веб-аналитики Google, предназначенная для сбора, обработки и анализа данных о взаимодействиях пользователей с сайтами и приложениями.

С помощью GA4 можно:
- определять количество пользователей и посещений;
- анализировать источники переходов на сайт;
- отслеживать просмотры страниц;
- изучать действия посетителей;
- оценивать взаимодействия пользователей с элементами сайта;
- анализировать целевые действия и конверсии;
- определять эффективность каналов привлечения аудитории.

Главная задача веб-аналитики заключается не только в подсчёте посетителей, но и в понимании их поведения. Анализ собранных данных помогает оценивать эффективность продвижения и принимать решения по улучшению сайта.

### 3.2. Связь UTM-меток и GA4

UTM-метки - это параметры URL, которые позволяют определить источник перехода пользователя на сайт. Google Analytics 4 использует информацию об источниках трафика для формирования аналитических отчётов.

Пример ссылки с UTM-метками:

`https://example.com/?utm_source=telegram&utm_medium=social&utm_campaign=september`

Основные параметры:
- `utm_source` - источник перехода, например Telegram;
- `utm_medium` - канал привлечения, например social;
- `utm_campaign` - название кампании;
- `utm_content` - дополнительная информация о варианте объявления или ссылке;
- `utm_term` - параметр, который может использоваться для обозначения ключевого слова.

Принцип работы:

1. Для публикации создаётся ссылка с UTM-метками.
2. Пользователь переходит по этой ссылке на сайт.
3. При корректно настроенной аналитике сведения об источнике перехода передаются в GA4.
4. Пользователь выполняет действия на сайте.
5. В отчётах можно сопоставить источник трафика с последующими действиями посетителя.

UTM-метки помогают определить происхождение перехода, а GA4 позволяет анализировать поведение пользователя после посещения сайта.

### 3.3. Событийная модель GA4

В GA4 взаимодействия пользователей фиксируются с помощью событий. Событие представляет собой запись определённого действия или взаимодействия.

Примеры событий:
- `page_view` - просмотр страницы;
- `scroll` - прокрутка страницы до предусмотренного порога;
- `click` - клик, например по исходящей ссылке при включённых соответствующих измерениях;
- `generate_lead` - получение потенциального клиента;
- `sign_up` - регистрация;
- `purchase` - покупка.

События можно разделить на несколько категорий:

- **Автоматически собираемые** - фиксируются системой при выполнении необходимых условий.
- **Расширенные измерения** - собирают дополнительные виды взаимодействий при включённых настройках и установленном теге.
- **Рекомендуемые события** - события с названиями и параметрами, рекомендованными Google для определённых сценариев.
- **Специальные события** - создаются для задач конкретного проекта.

Не каждое действие пользователя автоматически регистрируется в GA4. Для отслеживания отправки заявок, регистрации или других целевых действий может потребоваться дополнительная настройка.

### 3.4. Конверсии и оценка эффективности

Конверсия - это значимое для проекта действие пользователя. В зависимости от задач сайта конверсией может быть отправка заявки, регистрация, покупка или другое целевое действие.

GA4 позволяет оценивать, насколько эффективно источники трафика приводят пользователей к нужному результату.

Например, при условных показателях:
- 320 пользователей пришли из определённого источника;
- 48 пользователей открыли страницу регистрации;
- 17 пользователей выполнили целевое действие.

Доля посетителей, открывших страницу регистрации:

48 / 320 × 100% = 15%.

Доля посетителей, выполнивших целевое действие:

17 / 320 × 100% ≈ 5,3%.

Это учебный пример, а не фактические показатели основного проекта.

Анализ конверсий позволяет сравнивать источники трафика и определять, какие из них приводят к наиболее значимым результатам.

### 3.5. Структура Google Analytics 4

Аналитическая система включает несколько уровней.

**Account (аккаунт)**

Верхний уровень организации аналитики. Может объединять несколько ресурсов.

**Property (ресурс)**

Основная единица аналитики, в которой собираются и обрабатываются данные сайта или приложения. В ресурсе находятся отчёты, события и настройки.

**Data Stream (поток данных)**

Источник данных, передаваемых в ресурс. Для сайта используется веб-поток, а для мобильных приложений предусмотрены потоки Android и iOS.

**Measurement ID (идентификатор измерения)**

Идентификатор веб-потока, начинающийся с `G-`. Он используется при настройке передачи данных сайта в GA4.

Общая структура:

`Account → Property → Data Stream → Measurement ID`

Эти компоненты обеспечивают организацию аналитики и связь сайта с соответствующим ресурсом.

### 3.6. Основные настройки ресурса

При создании и настройке ресурса GA4 используются следующие параметры:

- **Property name** - название ресурса;
- **Reporting time zone** - часовой пояс отчётности;
- **Currency** - валюта денежных показателей;
- **Industry category** - категория деятельности;
- **Business size** - размер организации;
- **Business objectives** - цели использования аналитики.

Часовой пояс влияет на распределение событий по календарным дням. Валюта применяется при отображении денежных показателей.

Бизнес-цели помогают адаптировать стандартные отчёты под задачи проекта, но сами по себе не обеспечивают автоматическое отслеживание всех целевых действий.

### 3.7. Веб-поток и Enhanced Measurement

Веб-поток связывает сайт с ресурсом Google Analytics 4.

При настройке веб-потока указываются адрес сайта, название потока и параметры сбора данных.

**Enhanced Measurement (расширенные измерения)** - функция, которая позволяет автоматически собирать некоторые дополнительные виды взаимодействий при наличии необходимой настройки аналитики.

В зависимости от включённых параметров могут отслеживаться:
- просмотры страниц;
- прокрутка страницы до определённого порога;
- клики по исходящим ссылкам;
- взаимодействия с некоторыми элементами форм;
- другие поддерживаемые действия.

Наличие веб-потока не означает, что сайт уже передаёт данные. Для этого необходимо подключить Google Tag или другой подходящий способ отправки событий.

### 3.8. Google Tag и проверка данных

Google Tag используется для передачи информации о взаимодействиях с сайтом в аналитические сервисы Google.

После подключения тега необходимо проверить, что события поступают в правильный ресурс GA4.

Для проверки используются:
- **Realtime** - отчёт о недавней активности;
- **DebugView** - представление событий в режиме отладки при соответствующей настройке;
- инструменты проверки установки тегов.

При отсутствии данных необходимо проверить корректность Measurement ID, установку тега, настройки сбора данных и возможные ограничения со стороны браузера или системы согласия на обработку данных.

### 3.9. Источники трафика и отчёты

GA4 позволяет анализировать источники привлечения пользователей и оценивать эффективность различных каналов.

В аналитике могут использоваться показатели:
- пользователи;
- сеансы;
- просмотры;
- события;
- вовлечённость;
- ключевые события и конверсии;
- источники и каналы трафика.

Эти показатели помогают определить, откуда приходят посетители, как они взаимодействуют с сайтом и какие действия выполняют.

Сочетание UTM-меток и GA4 позволяет связать параметры рекламных и информационных кампаний с поведением пользователей после перехода на сайт.
